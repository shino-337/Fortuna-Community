# Fortuna Deployment Checklist

Use this checklist to validate that a fresh user can deploy Fortuna from the repository.
For the full command flow, start with [Quickstart](../01-getting-started/QUICKSTART.md).

## 1. Choose Image Delivery

Recommended for users and multi-node clusters:

- Use published images from `ghcr.io/shino-337/fortuna-community`.
- Set `FORTUNA_REGISTRY` and `FORTUNA_VERSION` to a published tag. For the first public release use `v1.0.0`; `latest`, `sha-<12-char-commit>`, and manual workflow tags are also valid when published.
- Create `ghcr-pull` only when GHCR packages are private.

Developer/local path:

- Set `FORTUNA_PACKAGE_SOURCE=local`.
- Run `./scripts/pipeline/full-clean-database-rebuild-deploy.sh --full`.
- For multi-node without a registry, run `./scripts/utils/push-images-to-workers.sh`.
- Prefer a registry over copying/importing images on every worker.
- Treat `deploy/*.yaml` image tags generated by local scripts as local containerd tags unless the GitHub image workflow has published the same tag.

## 2. Required Inputs

```bash
export FORTUNA_REGISTRY="ghcr.io/shino-337/fortuna-community"
export FORTUNA_VERSION="v1.0.0"
export FORTUNA_JWT_SECRET="$(openssl rand -base64 32)"
export FORTUNA_POSTGRES_PASSWORD="$(openssl rand -base64 24 | tr -d '=+/ ' | cut -c1-24)"
export FORTUNA_DATABASE_URL="postgres://postgres:${FORTUNA_POSTGRES_PASSWORD}@postgres.fortuna.svc.cluster.local:5432/fortuna?sslmode=disable"
```

Optional but recommended outside local bootstrap:

```bash
export FORTUNA_ADMIN_PASSWORD="<strong-admin-password>"
```

If `FORTUNA_ADMIN_PASSWORD` is omitted on a fresh deployment, Fortuna creates `admin / Fortuna_ChangeMe_123!` and requires a password change before normal API/UI use.

## 3. Namespace, Secrets, Infrastructure

```bash
kubectl create namespace fortuna --dry-run=client -o yaml | kubectl apply -f -
./scripts/deploy/ensure-storage-class.sh
NAMESPACE=fortuna ./scripts/utils/create_mtls_secret.sh
./scripts/utils/ensure-fortuna-secrets.sh fortuna

kubectl apply -f deploy/infrastructure/postgresql-with-age.yaml
kubectl apply -f deploy/infrastructure/nats.yaml
kubectl apply -f deploy/fortuna-rbac.yaml
kubectl apply -f deploy/dashboard-nginx-configmap.yaml
```

If GHCR is private:

```bash
kubectl -n fortuna create secret docker-registry ghcr-pull \
  --docker-server=ghcr.io \
  --docker-username="$GITHUB_USER" \
  --docker-password="$GITHUB_TOKEN" \
  --dry-run=client -o yaml | kubectl apply -f -

kubectl -n fortuna patch serviceaccount fortuna-core -p '{"imagePullSecrets":[{"name":"ghcr-pull"}]}'
kubectl -n fortuna patch serviceaccount fortuna-agent -p '{"imagePullSecrets":[{"name":"ghcr-pull"}]}'
kubectl -n fortuna patch serviceaccount default -p '{"imagePullSecrets":[{"name":"ghcr-pull"}]}'
```

Equivalent YAML templates are available in `deploy/samples/ghcr-pull-secret.example.yaml` and `deploy/samples/ghcr-imagepullsecrets.example.yaml`.

## 4. Workloads

```bash
kubectl apply -f deploy/fortuna-core-deployment.yaml
kubectl apply -f deploy/fortuna-agent-daemonset.yaml
kubectl apply -f deploy/dashboard-deployment.yaml

kubectl -n fortuna set image deployment/fortuna-core core="${FORTUNA_REGISTRY}/fortuna-core:${FORTUNA_VERSION}"
kubectl -n fortuna set image daemonset/fortuna-agent agent="${FORTUNA_REGISTRY}/fortuna-agent:${FORTUNA_VERSION}"
kubectl -n fortuna set image deployment/fortuna-dashboard dashboard="${FORTUNA_REGISTRY}/fortuna-dashboard:${FORTUNA_VERSION}"
```

## 5. Rollout Verification

```bash
kubectl rollout status -n fortuna deployment/fortuna-core --timeout=180s
kubectl rollout status -n fortuna daemonset/fortuna-agent --timeout=180s
kubectl rollout status -n fortuna deployment/fortuna-dashboard --timeout=180s
kubectl get pods,svc -n fortuna -o wide
```

Expected:

- `fortuna-core-*`: `Running`, `READY 1/1`
- `fortuna-agent-*`: one pod per node, `Running`
- `fortuna-dashboard-*`: `Running`
- `postgres-*`: `Running`
- `nats-*`: `Running`

## 6. Auth Verification

For a fresh deployment without `FORTUNA_ADMIN_PASSWORD`:

```bash
CORE_POD="$(kubectl -n fortuna get pod -l app.kubernetes.io/component=core -o jsonpath='{.items[0].metadata.name}')"
kubectl -n fortuna exec "$CORE_POD" -- curl -s \
  -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Fortuna_ChangeMe_123!"}' | python3 -m json.tool
```

Expected response:

- `user.mustChangePassword` is `true`.
- `user.bootstrapCredential` is `true`.
- Normal data APIs return `403` with `password_change_required` until the password is changed.

If `FORTUNA_ADMIN_PASSWORD` was set, login with that value. Existing databases keep the current admin password; Core will not overwrite it with the bootstrap default.

## 7. Dashboard Access

```bash
kubectl port-forward --address 0.0.0.0 -n fortuna svc/fortuna-dashboard 8081:80
```

Open `http://127.0.0.1:8081/`.

After login, first-time bootstrap users must change password. Then verify:

- Dashboard loads.
- Resources show Kubernetes inventory after agent sync.
- Monitoring shows pipeline/runtime status.
- SBOM/CVE data appears after catalog load and pod scans.

## 8. Data And Runtime Verification

```bash
kubectl logs -n fortuna -l app.kubernetes.io/component=core --tail=80
kubectl logs -n fortuna -l app.kubernetes.io/component=agent --tail=80
kubectl exec -n fortuna deploy/postgres -- psql -U postgres -d fortuna -c \
  "select max(version), count(*) from schema_migrations;"
kubectl exec -n fortuna deploy/postgres -- psql -U postgres -d fortuna -c \
  "select username,must_change_password,bootstrap_credential from users order by id;"
```

Optional runtime/Falco path:

```bash
./scripts/deploy/install-falco-fortuna.sh
kubectl rollout restart -n fortuna daemonset/fortuna-agent
```

## 9. Common Fixes

- `401 Unauthorized` pulling GHCR: create `ghcr-pull` or make packages public.
- Pods run old code after rebuild: verify manifest tag, image ID, and rollout. See [Deployment](DEPLOYMENT.md).
- Multi-node local build cannot schedule images: use a registry, or run `./scripts/utils/push-images-to-workers.sh`.
- Bootstrap default does not work: confirm Core is running the image that includes migration 147, `fortuna-secrets/bootstrap-default-credential=true`, and the DB does not already have a different admin password.
