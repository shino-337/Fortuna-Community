## 🔍 Problem Statement

User requested: **"đã có hiệu quả, phân tích và điều chỉnh các màn hình khác tương tự"**

After v3.1.0 successfully standardized the top bar and GraphView layout, we need to apply the same standards to:
- Dashboard
- ServiceAccounts
- AuditLogs

### Issues Found:

#### All 3 Pages:
1. ❌ Using `min-h-screen` instead of `h-full`
2. ❌ Padding inconsistency: `px-4` instead of `px-6`
3. ❌ Not leveraging parent flex layout from App.tsx
4. ❌ Missing `overflow-y-auto` for scroll control

#### AuditLogs Specific:
5. ❌ Dark mode duplicate classes: `dark:bg-gray-700 dark:bg-gray-900`
6. ❌ Missing dark mode styling on:
   - Page title (`h1`)
   - Form labels
   - Select inputs
   - Buttons
   - Table headers
   - Table cells
   - Action badges
   - Pagination buttons

---

## ✅ Solution - Standard Page Layout Template

### Page Container Structure

```tsx
// ❌ OLD (v3.1.0 and before)
<div className="min-h-screen bg-gray-50 dark:bg-gray-900">
  <div className="container mx-auto px-4 py-6 max-w-7xl">
    {/* Content */}
  </div>
</div>

// ✅ NEW (v3.2.0)
<div className="h-full overflow-y-auto bg-gray-50 dark:bg-gray-900">
  <div className="container mx-auto px-6 py-6 max-w-7xl">
    {/* Content */}
  </div>
</div>
```

**Changes**:
- `min-h-screen` → `h-full` (fills parent flex-1)
- Added `overflow-y-auto` (enables scrolling)
- `px-4` → `px-6` (consistent with GraphView)

**Why this works**:
```
App.tsx:
  flex flex-col h-screen
    ├─ Navigation (fixed height)
    └─ flex-1 overflow-hidden (remaining space)
         └─ Routes
              └─ Page: h-full overflow-y-auto (fills flex-1, scrollable)
```
